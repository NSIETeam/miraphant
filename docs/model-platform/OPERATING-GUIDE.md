# Miraphant 积分与充值使用指引

状态：仓库开发版，未部署生产；真实收款未开放。入口依据默认主题当前路由，不能据此认为线上已可用。

## 客户入口

| 页面 | 路径 | 用途 |
|---|---|---|
| 积分钱包／充值 | `/console/wallet` | 查看可用、冻结、购买及赠送积分，选择充值套餐和渠道 |
| 收银台 | `/checkout/:orderId` | 微信扫码／支付宝电脑网站支付；展示实际订单与到账状态 |
| 充值订单 | `/console/orders` | 查询本人订单、可退金额，申请退款并查看进度 |
| 消耗记录 | `/console/usage` | 查看实际积分消耗 |
| 价格与估算 | `/pricing` | 查看费率草案、任务用量示例及计算假设 |
| 访问密钥 | `/console/keys` | 管理调用模型的凭证 |

尚未配置或未开通的渠道显示不可用。支付页面返回成功不直接加积分，到账以服务端验签及订单入账结果为准。

## 积分能做什么

建议兑换比例为 **1 元 = 100 积分**，首期套餐为 10／50／100／500 元，无赠送。最终售价和模型映射须在收款开放前确认。

以下均按标准档草案、单次调用、无缓存和额外工具费用估算：

| 示例任务 | 每次积分 | 1000 积分可完成的完整次数 |
|---|---:|---:|
| 简短问答 | 0.85 | 1176 |
| 商品文案初稿 | 2.10 | 476 |
| 长文摘要 | 6.00 | 166 |
| 较长翻译 | 7.50 | 133 |
| 带代码上下文的问答 | 11.00 | 90 |

**这些是可复算的定价示例，不是固定工作量或质量保证。** 高阶模型、多轮修改、长上下文和智能体多次调用会增加消耗。详细输入／输出假设见 [积分方案](points.md)。客户以积分记账；模型接口中的 token 计量字段继续兼容。

## 对账页面的当前边界

- 账单读取、渠道导入和追加备注分别授权；普通客户不能访问。
- 查看既有批次不要求开启新订单。缺少独立账单加密配置时禁止导入。
- 导入记录可能为处理中、失败、已导入或格式暂不支持。结果未知时先核对记录。
- 微信交易账单已有解析；支付宝目前仅保存来源证据，尚不能逐行核对。
- 查询请求、备注和外部引用都是追加记录，不会自动联系渠道，不代表差异已解决，不调整积分。
- 当前不覆盖缺少可靠申请时间的退款缺账判断。

## 开放收款前

1. 完成微信支付商户、企业支付宝及相应支付产品申请。资料清单见 [实施规格](README.md#4-支付商户准备)。
2. 确认正式模型、成本、积分售价、退款规则及历史余额转换方案。
3. 完成支付宝账单解析与支付对账，补齐退款异常重试和完整移动端验收。
4. 在隔离环境完成真实商户小额支付、退款和对账，再完成生产备份、迁移与发布验收。

当前代码及自动检查通过不等于完成上述收款条件。详细已验证范围见 [审核记录](REVIEW-GATES.md) 和 [页面验收](ROUTE-ACCEPTANCE.md)。

## 品牌与历史设置

默认界面统一使用 Miraphant 原始 SVG、浏览器图标、触屏图标和分享图。品牌状态页为只读；发行版入口指向 Miraphant 仓库，上游来源与 MIT 许可证单独保留。

系统设置要求当前有效的平台最高管理员会话。积分计费开启时，旧的美元额度、赠额、倍率和外部充值链接不能再修改；原始历史数据保留，不会自动兑换成积分。新积分售价和充值套餐分别在模型价格与套餐管理中维护。
