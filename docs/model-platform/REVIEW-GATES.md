### G1 接线审查清单

原积分迁移必须审查每一条余额写入路径，基础账本完成后继续接线，不得把独立账本单测通过视为网关已扣积分。

| 现有路径 | 接线要求 |
|---|---|
| `relay/controller/helper.go`、`text.go` | 去除跳过预扣的信任分支，冻结持久化；进程退出不能丢失结算任务 |
| `relay/controller/audio.go`、`image.go` | 未定义计价的能力明确禁用，禁止穿透到旧扣费 |
| `model/token.go` | 用户钱包与访问密钥预算同一事务；请求必须归属正确用户与密钥 |
| `model/cache.go` | 缓存不得独立决定余额；迁移后刷新，不能重放旧额度 |
| `model/utils.go` | 批量队列直接调用私有余额写函数，须禁止旧写入并定义切换排空策略 |
| `model/user.go` | 注册、邀请奖励、直接余额更新与删除用户全部覆盖；历史额度不自动赋值为积分 |
| `model/main.go` | 默认 root 初始巨额 quota 不得自动成为可消费或可退款积分 |
| `model/redemption.go` | 兑换码状态和积分入账一并提交，重复兑换不重复赠送 |
| `controller/user.go` | 管理员充值、修改用户不能覆盖账本余额；必须增量、原因及业务键 |

独立审核要求：幂等键必须校验完整业务参数，同一个键换用户、价格、金额或密钥应冲突；冻结后的价格不可被编辑覆盖。总输入包含缓存时先扣除缓存，推理输出若已计入输出总量则不得重复计费。极值运算要检出溢出，用户余额不足及访问密钥不足均不得产生部分写入。购买批次与赠送来源必须保留，以便后续退款及过期处理。
