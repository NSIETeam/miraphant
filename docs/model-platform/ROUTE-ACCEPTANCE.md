### 每条路由的验收记录必须包含

- 实际源码路由与接口；访问地址；所用账号角色；是否发生跳转。
- 桌面和窄屏渲染；可见标题、Logo、导航、主要动作和返回路径。
- 加载、空、失败、成功、失效会话状态；客户不能直访管理数据。
- 余额／订单等动态数据来自服务端；草案及未开通功能不得伪装已开放。
- 有写入能力的页面还需验证资源所有者、CSRF、限流、最新角色和必要二次认证。

## 实际旧入口去向

以下为待实现的兼容策略，跳转前仍须验证身份和权限；路径参数不能转为外部 URL。不能用把全部旧地址重定向首页的方式宣称覆盖完成。

| 旧路由（实际源码存在） | 兼容去向或处理 |
|---|---|
| `/channel`、`/channel/add`、`/channel/edit/:id` | `/admin/channels` 对应列表、创建或编辑；保存资源标识并验权 |
| `/user`、`/user/add`、`/user/edit/:id` | `/admin/users` 对应列表、创建或编辑；管理员权限 |
| `/user/edit`、`/panel/profile` | `/console/profile`，仅本人资料 |
| `/token`、`/token/add`、`/token/edit/:id` | `/console/keys` 对应列表、创建或编辑；保持本人范围 |
| `/topup`、`/panel/topup` | `/console/wallet`；不继续旧外部充值参数拼接 |
| `/log`、`/detail`、`/panel/log` | 按角色进入本人用量或授权管理查询；不把管理员旧日志直接公开 |
| `/redemption`、`/redemption/add`、`/redemption/edit/:id`、`/panel/redemption` | 后台兑换码管理；积分模式如尚未适配，明确禁用且保留历史记录 |
| `/setting`、`/panel/setting` | 管理配置入口，分别导航品牌、渠道、支付等实际模块 |
| `/panel`、`/panel/dashboard` | 按当前角色进入 `/console` 或 `/admin` |
| `/panel/channel`、`/panel/user`、`/panel/token` | 对应上表管理渠道、客户或本人密钥入口 |
| `/about` | 品牌／关于说明和上游许可声明，不删除法定或授权要求的归属 |
| `/chat` | 保留已支持文本调用的入口或明确转到接入帮助；不跳往未配置的外部聊天站 |
| `/midjourney` | 首期未定义图片计费，明确展示未开放，阻止调用旧额度路径 |
| `/oauth/github`、`/oauth/lark`、`/oauth/oidc` | 保留启用的认证回调；对应原流程验证失败和未配置状态 |
| `/login`、`/register`、`/reset`、`/user/reset` | 保留身份流程，在统一主题内完成品牌替换 |
| `/404`、`/panel/404`、通配路径 | 统一不存在页面和返回入口 |

默认与 air 的路由是根地址；berry 大部分管理路由带 `/panel`。统一主题上线时需固定实际服务主题并关闭未维护主题选择，避免旧界面继续暴露。
