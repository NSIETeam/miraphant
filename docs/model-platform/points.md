# 积分定价与“能做多少事情”估算

状态：建议方案，未上线。最终模型映射、成本、售价与历史迁移比例须在开通充值前确认。

## 单位与定价

**1 元＝100 积分，1 积分的购买价格为 0.01 元。** 积分是平台模型服务额度，不是 token 数量；同样的积分，使用不同模型、上下文或生成长度，完成的工作量会不同。

建议客户名称：积分余额、购买积分、赠送积分、冻结积分、可用积分、已用积分。API 凭证叫“访问密钥”。底层 `usage.prompt_tokens` 等协议字段保持不变，详细用量账单可解释原始 token 数。

首期套餐：

| 付款金额 | 购买积分 | 赠送积分 |
|---:|---:|---:|
| ¥10 | 1000 | 0 |
| ¥50 | 5000 | 0 |
| ¥100 | 10000 | 0 |
| ¥500 | 50000 | 0 |

建议购买积分不设置有效期。赠送积分单独记录来源与期限，优先消费临近过期赠送积分，再消费购买积分；购买积分按批次记录消耗，支持退款核算。历史赠送额度单独处理，不能套用新购规则。

## 可复算的任务例子

下表均按标准档、无缓存、单次成功调用、无额外工具计费；输入包含系统提示与历史上下文，输出包含供应商计费的推理量。标题只是示例任务，不承诺特定质量或固定中文字数。

| 示例任务 | 假设输入／输出 token | 积分／次 | 1000 积分最多可覆盖完整次数 |
|---|---:|---:|---:|
| 简短问答 | 500／300 | 0.85 | 1176 |
| 一条商品文案初稿 | 1000／800 | 2.10 | 476 |
| 一份长文摘要 | 8000／1000 | 6.00 | 166 |
| 一段较长翻译 | 3000／3000 | 7.50 | 133 |
| 一次带代码上下文的问答 | 10000／3000 | 11.00 | 90 |

例：文案消耗 = 1000 ÷ 1000 × 0.5 ＋ 800 ÷ 1000 × 2 = **2.10 积分**。

高阶档相同输入／输出量的费用为上述值的 10 倍。例如长文摘要为 60 积分，1000 积分可完成 16 次同规模调用。智能体任务可能多轮调用：若一项任务包含 10 次上述代码问答，标准档约 110 积分、高阶档约 1100 积分；上下文增长会进一步增加消耗。

客户页面必须写明：**“示例估算，实际消耗取决于模型、内容长度和调用次数。”** 显示所选档位和估算假设，不能默认展示标准档次数却实际选中高阶模型。

尚未指定模型、图片／音频／视频参数或工具调用次数时，显示“需选择模型／暂不支持估算”，不得给出虚构的完成次数。

## 计算与结算契约

基础公式：

`积分 = (未缓存输入 × 输入费率 + 缓存输入 × 缓存费率 + 计费输出 × 输出费率) / 1000 + 已确认的额外工具费用`

- 缓存输入必须是总输入的子集，不能重复计入；仅有总输入而无缓存数据时按对应价格规则处理并标记。
- 推理 token 若已经包含在输出总量中，不得再次相加。各供应商计量适配须明确定义。
- 存储为整数微积分，`1 积分 = 1000000 微积分`；钱存整数分，不用浮点数。
- 每次最终结算仅在微积分精度进行一次四舍五入（half-up），消费记录保留精确值；界面显示至 2 位，小于 0.01 的正数显示“<0.01”，详情显示精确值。不得每次向上取整到一整积分或一分积分。
- 每次请求开始时锁定价格版本；价格变更只影响后续请求，不重算旧账或在途请求。
- 开始前原子冻结可用积分预算，完成后按实际 usage 结算并释放余量。冻结和扣减必须校验用户预算及访问密钥限额，并发不透支。
- 无 usage 或供应商状态不明时标记待核实，保留有时限的冻结并查证，不凭空估算成最终扣费。后台须能处理超时冻结。
- 用户主动中断但已产生计费用量时，按已确认 usage 结算；平台内部故障及自动重试成本的承担规则须明确，不得对同一逻辑请求重复收费。
- 默认禁用自动跨价档降级／切换；需要更贵模型时重新检查预算与客户授权。

估算接口返回价格版本、模型／档位、输入假设、输出上限、估算积分及说明；它不等于实际结算凭证。计算器必须与账单使用同一份价格版本，避免前台承诺与后台收费不一致。
